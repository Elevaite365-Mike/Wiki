# Getting support

## Try these first

1. Search this wiki, press ++slash++ anywhere
2. [Tips & best practices](tips.md): covers the most common "why is my test doing that?" cases
3. The [command reference](../commands/index.md): parameter-level detail for every command
4. [IT access requirements](../quickstart/access-requirements.md): sign-in, IP allowlist, MFA and Conditional Access questions
5. The [public roadmap](https://roadmap.elevaite365.com/): your issue may already be scheduled

## Contact us

Email **[help@elevaite365.com](mailto:help@elevaite365.com)**, or use the in-app support option.

This is also the address for [requesting a new application](../quickstart/adding-applications.md) on your instance.

### What to include

A ticket with these usually gets resolved on the first reply:

- [ ] **The test and the run**, which script, which environment, and when it ran
- [ ] **What you expected** to happen
- [ ] **What happened instead**, including the exact error text
- [ ] **Which step** it failed on
- [ ] **When it started**, and whether it ever worked
- [ ] **How often**, every run, or one in five?

!!! warning "Don't send passwords"
    Support never needs a test user's password or secret key. Reference the test user by its description instead.

## Request a feature

Tell us what you're trying to achieve rather than the solution you have in mind. It usually leads somewhere better. Accepted requests appear on the [public roadmap](https://roadmap.elevaite365.com/), which updates every two weeks.
